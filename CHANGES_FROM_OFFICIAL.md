# Changes From Official Godot

Faster-Godot starts from Godot 4.6.3-stable and narrows the engine around a
desktop Forward+ profile. The detailed notes are split by change area:

| Hardware RTGI and path tracing: modes, denoising, fog model, probe depth reconstruction, alpha-scissor emissive sampling, VoxelGI/SDFGI coexistence, and particle stability | [docs/path_tracing_gi.md](docs/path_tracing_gi.md) |
| RTGI control alignment with measured behavior | `rtgi_energy` now multiplies the composited indirect GI in every RTGI mode; it used to scale only the path-traced primary in Full Scene Path-Traced GI and did nothing in Hybrid RTGI (Cornell occluded-region linear-luma ratio at energy 2.0: 1.00 before, 2.00 path-traced / 1.98 Hybrid after). `rtgi_samples_per_pixel` is honored by the path-traced primary lighting; on Cornell at 1080p (RTX 4080 SUPER), temporal sparkle per megapixel dropped from 128.9 at 1 sample to 61.0 at 2 (+0.26 ms) and 6.8 at 4 (+0.71 ms); presets pin it to 1 and the Custom preset exposes it. The None denoiser is a real bypass of the temporal stabilizer and spatial denoise polish for inspecting the accumulated signal. The inert `rtgi_wrc_strength` property was removed; a compatibility binding keeps the old setter/getter resolvable for prebuilt GDExtensions. The renderer also warns once when RTGI output is discarded or substituted. See [docs/path_tracing_gi.md](docs/path_tracing_gi.md). |
| RTGI direct-lighting reservoir reuse and shadow-noise reduction | The path-traced direct lighting is no longer an independent one-sample estimate per frame. Temporal and spatial reservoir reuse (ReSTIR) now runs for the path-traced screen primary: the renderer copies the seven reservoir and history textures the merge reads from the current frame to the previous-frame slots after the primary dispatch, and the temporal combine scales the carried reservoir weight by the same cap ratio it applies to the sample count, which keeps the estimate energy-correct instead of brightening frame over frame. On the 24-light reservoir stress scene this cuts the static-frame whole-image variance about 18 percent with the average luma unchanged. The temporal history also stopped resetting itself spuriously: the radiance signature is now compared once per frame instead of flip-flopping across the three or four per-frame dispatch flavors (which had been clearing reservoir history every frame), the light-change reset is keyed on stable light ids so a camera-driven re-sort no longer counts as a light-set change, and a smoothly moving or scaling emissive mesh no longer churns the candidate signature. Probe rays (world radiance cache and screen probes) no longer write the screen primary buffers or read and merge the screen reservoir, which removes a row-0 contamination and an out-of-bounds store. Directional lights are evaluated deterministically with their own shadow ray outside the reservoir, so a bright occluded sun can no longer win every importance-sampled candidate draw and starve the local lights that actually reach a surface. The screen primary's shadow-cone samples come from the blue-noise texture with a per-frame golden-ratio rotation, which dropped Cornell temporal sparkle per megapixel from 128.9 to 101.7 at 1080p (RTX 4080 SUPER) with the energy unchanged. The reservoir candidate count is a per-preset shadow-ray budget (`rendering/rtgi/direct_light/{performance,balanced,production}/ris_candidates`, 4/8/16); on the stress scene the balanced 8 is about 15 percent and the performance 4 about 22 percent faster than 16 per GPU frame, while production keeps the full count. A new `PathtracingDebugMode` view colors each pixel by its direct-lighting regime (deterministic per-light versus reservoir sampling) and reuse depth so the over-12-light seam is visible. The per-dispatch-flavor RT uniform set is cached instead of being freed and recreated three or four times per frame. See [docs/path_tracing_gi.md](docs/path_tracing_gi.md). |
| RTGI directional shadow angular size, multi-sample sun shadows, and indirect-energy GI semantics | The path-traced directional (sun) cone half-angle now uses the light's full angular diameter, matching the rasterizer's soft-shadow convention; it previously used half the diameter, so sun penumbrae came out about half as wide. Large suns take several stratified shadow-cone samples on the path-traced screen primary, scaled by the sun's solid angle and bounded by a per-preset budget `rendering/rtgi/direct_light/{performance,balanced,production}/shadow_samples` (1, 2, and 4); a small sun stays at one sample, and the probe and deep paths keep a single sample. On a directional penumbra-ramp scene the balanced two-sample setting cut the soft-edge noise about 40 percent with the penumbra width unchanged. A light's indirect energy multiplier now also scales its contribution to the path-traced probe-gathered global illumination, the same way it already works for VoxelGI and SDFGI; the directly visible shading is not scaled. See [docs/path_tracing_gi.md](docs/path_tracing_gi.md). |
| Area light (LTC AreaLight3D) port from 4.7, plus path-traced area lights under RTGI | The 4.7 rectangular `AreaLight3D` is ported to the Forward+ raster path (LTC diffuse, specular, textured emission, and PCSS soft shadows). Under the fork's `radiance_probes` RTGI the path tracer shades the same light analytically with the Linearly Transformed Cosines closed form instead of treating it as a point at the rectangle's center: it reads the same LTC tables and area-texture atlas as the rasterizer, measures distance attenuation to the closest point on the rectangle so the lit pool stretches with a long thin light, and matches the raster pool to about one percent (mean luma 0.777 against 0.769). Soft shadows use a shared-sample visibility ratio: the same stratified samples on the rectangle drive a visible and a total cosine sum, so the light radiance cancels and only the visibility fraction remains, which dropped the contact-shadow band noise about 22 percent versus a single shadow ray at the same cost. `Environment.rtgi_area_light_gi_quality` (Fast, the default, or High) trades probe-gather shadow cost for quality; the camera-visible shading always uses the full ratio. The area light is evaluated outside the path tracer's reservoir, so the omni, spot, directional, and emissive paths stay byte-identical. See [docs/arealight3d.md](docs/arealight3d.md). |

| GLTF/GLB Draco mesh import | The GLTF importer now supports existing Blender-style `KHR_draco_mesh_compression` assets by bundling a decoder-only Google Draco 1.5.7 source subset in `thirdparty/draco`, expanding compressed mesh primitives into transient in-memory accessors before normal mesh parsing, and reporting `KHR_draco_mesh_compression` from `GLTFDocument.get_supported_gltf_extensions()`. This is importer-only: Faster-Godot does not export Draco-compressed GLTF/GLB files and does not add a `.blend` importer option to make Blender emit Draco during temporary export. |
| GLTF/GLB meshopt and quantized mesh import | The GLTF importer now expands `EXT_meshopt_compression` buffer views with the existing `thirdparty/meshoptimizer` decoder before normal accessor parsing, and reports `KHR_mesh_quantization` for default `gltfpack -c` output. This is importer-only; Faster-Godot does not export meshopt-compressed or quantized GLTF/GLB files. |
